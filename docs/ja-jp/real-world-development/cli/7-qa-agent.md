`quality-checks` スキルで自動チェックを実行し、Playwright の Model Context Protocol (MCP) サーバーでブラウザー上のフィルタリング操作を確認しました。次は、明確な品質保証 (QA) プロセスを持つカスタムエージェントにこれらの機能をまとめます。

このレッスンでは、次の内容を学習します。

- カスタムエージェントが指示、スキル、MCP ツールと連携する仕組みを確認する。
- 再利用可能な品質保証プロファイルを作成して確認する。
- QA エージェントを選択し、フィルタリングの Issue に照らして指摘を確認する。

## シナリオ

Tailspin Toys では、プルリクエスト (PR) を作成する前に、要件、コード品質、自動チェック、テストカバレッジ、ブラウザー上の動作を一貫して確認したいと考えています。カスタムエージェントは、この QA プロセスを調整し、再利用できるレポートを作成できます。

## カスタムエージェントとは

カスタムエージェントは、Markdown プロファイルで定義する専門化された Copilot です。プロファイルにはエージェントの目的、指示、利用可能なツールを記述します。このワークショップでは、`.github/agents/qa.agent.md` に QA の役割を定義し、Copilot CLI で選択します。

これまでに使ったカスタマイズは、それぞれ異なる役割を担います。リポジトリの指示はチームの標準を説明し、`quality-checks` スキルは繰り返し実行できるチェックをまとめます。Playwright MCP はブラウザーツールを提供します。QA プロファイルは、それらを使って要件を評価し、結果を報告するよう Copilot に指示します。これらを置き換えるものではなく、新しい会話も必要ありません。

## QA プロファイルを作成する

機能の PR を開く前に、再利用可能な QA プロファイルを Copilot に作成させます。プロファイルには、QA が行うチェックと守るべき境界の両方を定義します。

1. Codespace に戻り、フィルタリングの会話が Interactive モードであることを確認します。
2. 既定のエージェントに、新しいカスタムエージェントを作成するよう依頼します。

   ```plaintext
   .github/agents/qa.agent.md に QA という名前のカスタムエージェントを作成してください。機能を Issue と合意済みの要件に照らして確認し、リポジトリの指示に従い、quality-checks スキルを実行し、Playwright MCP で動作を検証してください。テストカバレッジが不足している場合はテストを追加してください。

   各要件について、根拠を添えて pass、fail、blocked のいずれかで報告してください。実装コードを変更する前に確認を求め、変更をコミットしたりプルリクエストを開いたりしてはいけません。

   まずはレビュー用にプロファイルだけを作成してください。
   ```

## プロファイルを確認する

新しいエージェントを使う前に、Copilot が意図した QA の流れと制約を正しく反映したことを確認します。これにより、検証だけを行いたいときに、指示が不十分だったり範囲が広すぎたりするエージェントが機能を変更するのを防げます。

1. `/diff` を入力し、`.github/agents/qa.agent.md` を開きます。
2. フロントマターを確認します。`description` は必須です。`name` は省略可能ですが、記述するとエージェントの表示名が明確になります。
3. プロファイルの指示を読み、QA が要件を起点とし、リポジトリの指示に従い、`quality-checks` スキルを実行して Playwright MCP を使うことを確認します。
4. QA が根拠を報告し、実装コードの変更前に確認を求め、変更をコミットしたりプルリクエストを開いたりしないことを確認します。
5. 必要な責務や制約が欠けている場合は、続行する前に既定のエージェントにプロファイルの修正を依頼します。

## Issue に対して QA を実行する

Copilot CLI は会話開始時にプロジェクトのエージェントを読み込みます。プロファイル作成後に同じフィルタリングの会話を再開し、QA を選択すると、Issue と計画時の決定を引き継いで確認できます。

1. 次のプロンプトを使って QA エージェントを有効にします。

   ```plaintext
   /agent QA
   ```

> [!NOTE]
> 作成したばかりのエージェントは、利用可能なエージェント一覧に表示されない場合があります。上記のコマンドで有効にできます。

2. 次のプロンプトで、QA エージェントに機能をレビューするよう依頼します。

   ```plaintext
   Issue と計画で合意した内容に照らして、フィルタリング機能をレビューしてください。PR を作成できる状態ですか。
   ```

3. QA エージェントが作業する様子を確認します。
4. 作業が完了したら、レポートを読みます。

## まとめと次のステップ

再利用可能な専門的役割をワークフローに加え、その結果を確認しました。このレッスンでは、次の作業を行いました。

- カスタムエージェントと指示、スキル、MCP ツールとの連携を確認しました。
- 再利用可能な品質保証プロファイルを作成して確認しました。
- QA エージェントを選択し、フィルタリングの Issue に照らした指摘を確認しました。

これで、実装、スキルの更新、QA プロファイル、テスト、検証レポートが揃いました。次は、それらを機能 PR にまとめ、[Agent Merge を使います][next-lesson]。
