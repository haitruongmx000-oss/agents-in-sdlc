GitHub Copilot を agent mode で使うと、コードベースの調査、変更の提案、ファイルの編集、コマンドの実行などを自律的に行います。この作業は開発者のマシンでリアルタイムに進むため、VS Code の Copilot Chat ではツール呼び出しやファイル編集を確認できます。差分をインラインでレビューし、変更ごとに採用または取り消し、エディターを離れずに追加のプロンプトを送り、作業の調整や拡張を行えます。

この演習では、次の内容を学習します。

- アクセシビリティエージェントの作業をリアルタイムで監視する。
- 提案されたファイル編集をレビューして採用する。
- セッションの途中でエージェントを誘導し、ハイコントラストとともにライトモードの切り替えを追加する。

## シナリオ

[演習 4][previous-lesson] で使ったアクセシビリティのカスタムエージェントが、ハイコントラストモードを実装しています。作業中にデザインチームから追加の依頼がありました。既定のテーマが暗すぎると感じるユーザー向けに、ライトモードの切り替えも追加します。新しい会話を最初から始めずに、既存のセッションを誘導して作業を拡張します。

## Copilot の進捗を監視する

Copilot Chat ビューには、エージェントが行う各手順、調査したファイル、実行したコマンド、提案した編集が表示されます。ファイル編集は差分と **Keep** / **Undo** の操作とともにチャット内に表示されます。

1. 演習 4 で使った Copilot Chat ビューに戻ります。
2. エージェントの作業中にチャットをスクロールし、各ツール呼び出しを確認します。ファイルの読み取り、編集、実行を求めるターミナルコマンドが表示されます。
3. エージェントがファイルの編集を提案すると、差分がチャット内に表示されます。
   - **Keep** を選択すると変更を採用します。
   - **Undo** を選択すると変更を取り消し、エージェントに再度作業させます。
4. チャット上部の **Files changed** を開くと、このセッション中にエージェントが変更したファイル全体を確認できます。

> [!NOTE]
> ターミナルコマンドの実行などに許可が必要な場合、エージェントは一時停止して **Allow** を表示します。許可するのは、内容を確認して問題がないコマンドだけにしてください。

5. エージェントがハイコントラストモードの実装を完了するまで待ちます。完了すると、変更内容の概要が表示されます。

## エージェントを誘導してライトモードを追加する

ハイコントラストモードの実装が完了したら、同じ会話でライトモードの切り替えを追加します。同じチャットセッションを続けることで、エージェントは前の作業のコンテキストを保持します。変更したコンポーネント、スタイルの方針、local storage を使ったパターンなどを把握しています。

1. Copilot Chat の入力欄に、次の追加プロンプトを送信します。

   ```plaintext
   よくできました。ハイコントラストの切り替えに加えて、ライトモードの切り替えも追加してください。同じ方法で local storage に設定を保存し、同じユーザーインターフェイス (UI) 領域から選べるようにしてください。ユーザーがハイコントラストとライトモードを個別に有効にできるようにしてください。
   ```

2. エージェントは前の作業を確認し、ライトモードの追加を提案します。
3. ハイコントラストのときと同じように、新しい編集をひとつずつ確認し、差分ごとに **Keep** または **Undo** を選択します。
4. エージェントの作業が意図と異なる場合は、たとえば切り替え UI を意図しない方法でリファクタリングしようとしたとき、チャット入力欄の横にある **Stop** を選択して停止し、明確な追加プロンプトを送信します。

> [!TIP]
> 作業中のセッションを誘導する方が、最初からやり直すよりも速く進められます。追加プロンプトで調整を依頼できます (例: 「カスケーディングスタイルシート (CSS) を簡潔にし、セレクターの重複ではなく CSS 変数を使う」)。方向を修正できます (例: 「3 つ目の切り替えを追加せず、ライトモードを既存の設定パネルに組み込む」)。範囲を広げることもできます (例: 「両方の切り替えにキーボードショートカットも追加する」)。

## 変更された作業ファイルをレビューする

変更をコミットする前に、エージェントが編集したファイルを簡単に確認します。

1. VS Code の **Source Control** ビューを開きます。
2. 変更されたファイルの一覧を確認します。Astro コンポーネント、スタイル、関連テストなどが含まれます。
3. 変更されたファイルをいくつか開き、差分を確認します。カスタムエージェントが求めるアクセシビリティパターン (Accessible Rich Internet Applications (ARIA) 属性、キーボード操作、セマンティックな HyperText Markup Language (HTML)、local storage による設定の保持など) が反映されていることを確認します。
4. 内容に問題がなければ、Source Control パネルから変更をステージングしてコミットします。次のレッスンで公開します。

## まとめと次のステップ

Copilot Chat の agent mode を使い、進行中のセッションを監視して誘導しました。ファイル編集を確認し、変更を採用または取り消し、コンテキストを保ったまま追加プロンプトで作業を広げました。

このレッスンでは、次の内容を確認しました。

- エージェントの作業をリアルタイムで監視する。
- ファイル編集を個別に採用または取り消す。
- 追加プロンプトを使い、作業中のセッションを誘導する。

[次のレッスン][next-lesson]では、アクセシビリティ機能をプルリクエストとして公開し、このラボでローカルのカスタムエージェントが行った変更をレビューします。
